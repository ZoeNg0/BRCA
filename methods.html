Section 03

Methods

How the gene expression and clinical data were analysed, including the statistical methods used at each step, the software versions, and how the analysis can be reproduced.

Analysis overview

The eight stages of the analysis, from downloading the data to exporting the figures.

1. AcquireGDC and GEO, cached once
2. TestOne DE method per platform
3. AggregateCombine five cohorts by rank
4. Shortlist260 replicated genes
5. CharacteriseSurvival, subtype, confounders
6. ConnectCo-expression network, hubs
7. InterpretDirected enrichment test
8. ExportPlots and tables for this site

Each stage was run as a separate, numbered R script, in order. Later stages reuse the saved output of earlier ones.

Analysis steps

What was done at each stage, which method was used, and why.

  1. Downloading the data

    TCGA gene expression counts, clinical data and somatic mutation calls were downloaded from the Genomic Data Commons (GDC) using the R package TCGAbiolinks. The expression data were STAR gene counts (unstranded) for primary tumours and normal tissue samples. All downloads, including the GEO datasets, were saved as R objects so the analysis could be re-run without downloading the data again. GSE58135 needed extra processing because GEO only provides an FPKM file for each sample, not raw counts. Its data table was assembled during download, and its 28 cell lines were removed at that stage.

  2. Differential expression

    Differential expression analysis tests each gene for a difference in expression between two groups, here tumour and normal tissue. For each gene it gives a log₂ fold change (how much higher or lower the gene is in tumours, where +1 means twice as high) and an adjusted p-value. Because the five datasets were measured in different ways, each was analysed with a method suited to its type of data. TCGA was analysed with DESeq2, which is designed for RNA-seq counts, using design = ~ sample_type with normal tissue as the reference group, so that a positive fold change means “higher in tumour”. GSE70947 was analysed with limma, a linear-model method widely used for microarrays, with patient included in the model. Since every patient in this dataset has both a tumour and a normal sample, this removes differences between individuals, which is the main reason this dataset carries the most weight. GSE58135 has no raw counts, so limma-trend was applied to log₂(FPKM + 1) values; this version of limma accounts for how the variability of a gene depends on its expression level. The two Affymetrix datasets had already been processed with RMA (a standard microarray normalisation method) and were quantile-normalised across arrays before the same tumour-versus-normal comparison.

  3. Combining the five datasets

    A simple approach would be to keep only genes that are significant in all five datasets, but this depends heavily on the chosen cutoff and penalises smaller datasets, which have less statistical power. Instead, the genes in each dataset were ranked by signed −log₁₀ p, a score that combines the direction and strength of the change, and the five rankings were combined using robust rank aggregation (RRA). RRA gives a gene a low p-value if it ranks near the top consistently across datasets. Increases and decreases were combined separately, so a gene that goes up in one dataset and down in another doesn't score well in either list. Only the 7,311 genes measured in all five datasets could be included. Genes outside this set were not tested, which is different from being shown to have no effect.

  4. Shortlisting replicated genes

    RRA identified 294 genes higher in tumours and 615 lower in tumours at adjusted p < 0.05. The shortlist contains the 260 of these that were also individually significant, in the same direction, in all five datasets. As a sanity check, the genes higher in tumours were mostly involved in cell division, and the genes lower in tumours were mostly typical of fat and connective tissue (stroma). This is expected, since normal breast tissue is largely fat and stroma. It suggests the analysis was set up correctly, but it isn't a new finding.

  5. Survival and subtype analysis

    For survival analysis, patients were split into PPP4C-high and PPP4C-low groups at the median expression value. The median was chosen in advance, because searching for the cutoff that gives the smallest p-value makes a result look more significant than it really is. Kaplan–Meier curves, shown with 95% confidence bands, estimate the proportion of patients still alive over time in each group. The log-rank test checks whether the two curves differ. Follow-up was limited to five years. A Cox proportional hazards model was then used to estimate the hazard ratio (the relative risk of death in the PPP4C-high group compared with the PPP4C-low group) while adjusting for stage, age and subtype. The Cox model assumes the hazard ratio stays roughly constant over time, so this assumption was tested using Schoenfeld residuals. Two sensitivity analyses checked whether the result depended on where patients were split: one compared the top 40% with the bottom 40% of patients, leaving out the middle fifth, and the other repeated the analysis with 50/50, 60/40, 70/30, 80/20 and 90/10 splits. Subtypes were compared with non-parametric tests, which don't assume normally distributed data and are better suited to groups of very different sizes.

  6. Co-expression network

    A co-expression network connects genes whose expression levels rise and fall together across samples. Genes connected to many others are called hubs, and they often point to the main biological processes in the data. The network started with the 10,184 genes that were differentially expressed in TCGA, filtered to the 4,563 that were consistently expressed across the cohort. Two genes were connected if their Spearman correlation (a rank-based measure of how closely two variables move together) was at least 0.70 in either direction across the 1,095 tumours. This produced 20,326 connections, and the Louvain algorithm divided the network into 143 modules, which are groups of closely connected genes. The 200 most connected genes, with 71 to 172 connections each, were defined as hubs. No connections were added from external interaction databases such as STRING or BioGRID, so the network reflects only the TCGA data.

  7. Gene set enrichment

    Enrichment analysis tests whether a group of genes, here the 200 hubs, contains more members of a known biological pathway than would be expected by chance. An initial search across twenty databases found 3,034 significant terms at FDR < 0.05 (FDR, the false discovery rate, is the expected proportion of false positives among the significant results). This was run against two backgrounds: all expressed genes, to see which processes the hubs are involved in, and all other differentially expressed genes, to see what distinguishes hubs from other genes that change in tumours. A list of significant results can't show that a process is absent, so a second, targeted test was also run. Standard proliferation and motility gene sets were chosen in advance, and every result was reported whether it was significant or not. This is the test shown in Results Figure 6, where non-significant sets are faded instead of removed.

  8. Separating tumour cell and stromal signals

    Bulk tissue samples contain cancer cells mixed with other cell types, so a signal in the data doesn't necessarily come from the cancer cells. One module had a strong EMT (epithelial–mesenchymal transition) signature, which could suggest cancer cells becoming more mobile. To test where it came from, each module was scored in every tumour and correlated with markers of specific cell types. The EMT module correlated at +0.86 with fibroblast content and −0.14 with epithelial content. If the signal came from cancer cells changing state, it would be expected to increase with epithelial content, so the module most likely reflects the amount of fibroblast tissue in each sample. The proliferation module showed the opposite pattern, consistent with it coming from the cancer cells themselves.

  9. Exporting results to this website

    Each figure was exported from the analysis together with its underlying data table and a record of how it was produced. No values were recalculated or created at this stage. The export was set to stop if a figure didn't match the analysis; for example, the survival export only runs if its recalculated sample size, number of deaths, hazard ratio and log-rank p-value match the original analysis.

Reproducing the analysis

How the code is organised so the analysis can be run again.

The analysis code is in a separate GitHub repository, and this website contains only the exported results. Each stage is a separate script that runs in order. Downloaded data is saved locally and each step can be re-run on its own, so the analysis can be repeated without downloading the data again. Each script also saves a record of its inputs, settings and software versions alongside its output.
