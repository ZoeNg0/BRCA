Section 03

Methods

The pipeline from downloaded counts to finished figure, written so that a reader with the same data could run it and get the same answer.

Pipeline overview

1. AcquireGDC and GEO, cached once
2. TestOne DE method per platform
3. AggregateCombine five cohorts by rank
4. Shortlist260 replicated genes
5. CharacteriseSurvival, subtype, confounders
6. ConnectCo-expression network, hubs
7. InterpretDirected enrichment test
8. ExportPlots and tables for this site

Each stage is one numbered R script, run in dependency order. Nothing downstream re-downloads or re-fits what an earlier stage already produced.

Step by step

  1. Acquisition

    TCGA expression, clinical tables and somatic mutation calls are pulled from the GDC with TCGAbiolinks — STAR counts, unstranded assay, primary tumours and solid-tissue normals — then cached as R objects so nothing re-downloads. The GEO series are cached the same way. GSE58135 needs different handling: GEO holds no raw counts for it, only per-sample FPKM tracking files, so its matrix is assembled during download and its 28 cell lines are excluded at that point rather than filtered out later.

  2. Differential expression, one method per platform

    TCGA uses DESeq2 with design = ~ sample_type, the reference level set to normal tissue so a positive log₂ fold change always means “up in tumour”. GSE70947 uses limma with the design blocked on patient, which removes inter-patient variance and is the whole reason that cohort carries the most weight. GSE58135 has no counts, so limma-trend models the mean–variance relationship of log₂(FPKM + 1) directly. The two Affymetrix cohorts arrive RMA-processed and get a cross-array quantile normalisation before the same two-group contrast. Matching the model to the measurement matters more than using one model everywhere.

  3. Combining cohorts by rank, not by intersection

    The obvious rule — keep genes significant in all five cohorts — is very sensitive to an arbitrary threshold and punishes the smaller cohorts for being small. Instead each cohort is ranked independently by signed −log₁₀ p, and the rankings are combined with robust rank aggregation, so a gene rises by being consistently near the top. Up and down directions are aggregated separately, so a gene that moves one way in one cohort and the other way elsewhere is penalised in both lists. The analysis is restricted to the 7,311 genes measured in all five cohorts; a gene outside that set is untested, not disproved.

  4. From 8,186 candidates to 260

    Rank aggregation returns 294 up and 615 down at adjusted p < 0.05, and the shortlist keeps the 260 genes that are also individually significant, in the same direction, in every one of the five cohorts. Two sanity checks come free: the up list is dominated by mitotic machinery and the down list is an adipose and stromal loss signature — exactly what comparing tumour against normal breast, which is largely fat and stroma, should produce. That is evidence the pipeline is wired correctly, not a discovery.

  5. Characterising a candidate, and guarding against its confounders

    Survival uses a pre-specified median split rather than the cut-point that minimises p, which would inflate significance badly; Kaplan–Meier with 95% bands and a log-rank test, censored at five years, then Cox adjusted for stage, age and subtype, with the proportional-hazards assumption checked rather than assumed. Two sensitivity analyses guard the split: a top-40%-versus-bottom-40% comparison with the middle fifth dropped rather than reassigned, and a sweep across 50/50, 60/40, 70/30, 80/20 and 90/10. Subtype comparisons use non-parametric tests, because the group sizes differ by more than an order of magnitude.

  6. Building the co-expression network

    “Hub” is a property of a network, so the network is built before anything is called a hub: the 10,184 TCGA differentially expressed genes are filtered to 4,563 that are actually expressed across the cohort, joined by 20,326 edges wherever two genes correlate at |Spearman ρ| ≥ 0.70 across the 1,095 tumours, and split into 143 modules. The 200 most connected genes — degree 71 to 172 — are the hubs. No external interaction database contributes an edge: STRING or BioGRID would import evidence from other tissues and experiments, which is precisely what a TCGA-only analysis excludes.

  7. Asking the enrichment question in a way that can return “no”

    A first pass over twenty databases returns 3,034 terms at FDR < 0.05, tested against two backgrounds that answer different questions: against all expressed genes, what biology are the hubs part of; against the other differentially expressed genes, what makes a hub different from any ordinary tumour-altered gene. But “what passed” is the wrong instrument for “is motility involved?”, so a second, directed test names the canonical proliferation and motility sets in advance and reports every one of them whether it passes or not. That is what Results Figure 6 draws, and it is why a failing set is faded on that figure rather than deleted from it.

  8. Testing whether a signal is tumour or stroma

    One module in the network does carry a strong EMT signature, which would be a real finding if it came from the cancer cells. Each module is scored per tumour and correlated against markers whose cellular origin is not in doubt. That module tracks fibroblast content at +0.86 and epithelial content at −0.14 — cancer cells changing state would move with epithelial content, not against it. So it is measuring how much fibroblast is admixed in each bulk sample. The proliferation module behaves the opposite way, and is a programme of the carcinoma cells themselves.

  9. Export to this website

    Every figure on this site is exported from the analysis together with the table of values behind it and a record of how it was produced. Nothing is recomputed at that stage and nothing is synthesised: the export aborts rather than publish a figure that disagrees with the analysis. The survival export, for instance, refuses to run unless the recomputed sample count, event count, hazard ratio and log-rank p match the values the analysis itself reported — so the site and the analysis cannot quietly drift apart.

Reproducibility

Analysis code lives in a separate repository; this site holds only the exported results. Each stage is a separate script run in dependency order, every download is cached, and each step is independently re-runnable, so repeating the analysis costs compute rather than bandwidth. Each script writes a record of its own inputs, parameters and software versions alongside its output.
