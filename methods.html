Section 03

Methods

How the raw data was turned into the figures on this site, step by step, so anyone with the same data could get the same answer.

Pipeline overview

1. AcquireGDC and GEO, cached once
2. TestOne DE method per platform
3. AggregateCombine five cohorts by rank
4. Shortlist260 replicated genes
5. CharacteriseSurvival, subtype, confounders
6. ConnectCo-expression network, hubs
7. InterpretDirected enrichment test
8. ExportPlots and tables for this site

Each stage is a numbered R script, run in order. Later stages reuse what earlier ones produced instead of downloading or fitting it again.

Step by step

  1. Downloading the data

    I downloaded TCGA expression data, clinical tables and somatic mutation calls from the GDC using TCGAbiolinks (STAR counts, unstranded, primary tumours and normal tissue) and saved them as R objects so I'd only need to download them once. The GEO datasets were saved the same way. GSE58135 needed extra work because GEO doesn't have raw counts for it, only an FPKM file per sample, so I built its data table during the download and removed its 28 cell lines at that point.

  2. Differential expression

    For TCGA I used DESeq2 with design = ~ sample_type and normal tissue as the reference level, so a positive log₂ fold change means “higher in tumour”. GSE70947 used limma with patient included in the design, which removes variation between patients and is the main reason that cohort carries the most weight. GSE58135 has no raw counts, so I used limma-trend on log₂(FPKM + 1), which models the mean–variance relationship directly. The two Affymetrix cohorts were already RMA-processed, so they got quantile normalisation across arrays and then the same two-group comparison. I matched each model to the type of data instead of forcing one model onto all five.

  3. Combining the five cohorts

    The simplest approach would be to keep genes that are significant in all five cohorts, but the result depends a lot on where the cutoff is set, and smaller cohorts get penalised for having less power. Instead I ranked each cohort's genes separately by signed −log₁₀ p and combined the rankings with robust rank aggregation, so a gene scores well if it's consistently near the top. Up and down were combined separately, which penalises a gene that goes up in one cohort and down in another. Only the 7,311 genes measured in all five cohorts could be included, so a gene outside that set hasn't been tested, which isn't the same as being ruled out.

  4. Shortlisting genes

    Rank aggregation gave 294 up and 615 down genes at adjusted p < 0.05. The shortlist is the 260 of these that are also individually significant, in the same direction, in all five cohorts. As a sanity check, the up list is mostly cell division genes and the down list is mostly fat and connective tissue (stroma) genes. That's expected, since normal breast tissue is mostly fat and stroma. It confirms the pipeline is set up correctly, but it isn't a new finding.

  5. Survival and subtype analysis

    For survival I split patients at the median PPP4C value, decided in advance, because choosing the cut-point that gives the smallest p-value inflates significance a lot. I used Kaplan–Meier curves with 95% bands and a log-rank test, censored at five years, then a Cox model adjusted for stage, age and subtype, and checked the proportional-hazards assumption. Two sensitivity analyses tested the split. One compared the top 40% with the bottom 40%, dropping the middle fifth. The other tried 50/50, 60/40, 70/30, 80/20 and 90/10 splits. For subtypes I used non-parametric tests, since group sizes differ by more than tenfold.

  6. Co-expression network

    A hub only makes sense within a network, so I built the network first. I started with the 10,184 genes differentially expressed in TCGA and filtered them to the 4,563 actually expressed across the cohort. Two genes were connected if their expression correlated at |Spearman ρ| ≥ 0.70 across the 1,095 tumours, which gave 20,326 connections (edges), and the network split into 143 modules. The hubs are the 200 most connected genes, with 71 to 172 connections each. I didn't add edges from interaction databases like STRING or BioGRID, because those include evidence from other tissues and experiments and I wanted the network to come from TCGA only.

  7. Gene set enrichment

    A first pass across twenty databases found 3,034 terms at FDR < 0.05. I tested against two backgrounds. Using all expressed genes asks what biology the hubs are involved in. Using the other differentially expressed genes asks what sets hubs apart from other genes that change in tumours. A list of significant terms can't really tell you whether motility is involved, though, so I also ran a targeted test. I picked the standard proliferation and motility gene sets in advance and reported every one, whether it passed or not. That's what Results Figure 6 shows, and the sets that failed are faded on the figure instead of removed.

  8. Tumour cells versus stroma

    One module had a strong EMT signature, which would be interesting if it came from the cancer cells. To check, I scored each module in every tumour and correlated the scores with markers for specific cell types. That module correlated +0.86 with fibroblast content and −0.14 with epithelial content. If cancer cells were changing state, it should have gone up with epithelial content. So the module mostly reflects how many fibroblasts were in each bulk sample. The proliferation module showed the opposite pattern and comes from the cancer cells themselves.

  9. Exporting figures

    Each figure on the site is exported from the analysis with the table of values behind it and a record of how it was made. Nothing is recalculated or made up at this stage, and if a figure doesn't match the analysis, the export stops. For example, the survival export only runs if the sample count, event count, hazard ratio and log-rank p it recalculates match the values from the analysis, so the site can't drift out of sync with the results.

Reproducibility

The analysis code is in a separate repository, and this site only contains the exported results. Each stage is a separate script run in order. Downloads are saved locally and each step can be re-run on its own, so repeating the analysis only costs computing time. Every script also saves its inputs, settings and software versions alongside its output.
