Section 03

Methods

The pipeline from downloaded counts to finished figure, written so that a reader with the same data could run it and get the same answer.

Pipeline overview

1. AcquireGDC download, manifest pinned
2. CleanFilter samples and genes
3. NormaliseVST / TPM, batch check
4. ExplorePCA, clustering
5. TestDifferential expression
6. InterpretPathway enrichment
7. ModelKaplan-Meier, Cox
8. ValidateMETABRIC replication

Step by step

  1. Acquisition

    Expression counts and clinical annotations are pulled from the GDC with a saved manifest, so the exact file versions are recoverable later. Clinical fields are reduced to the ones actually used: subtype, stage, age at diagnosis, vital status and follow-up time.

  2. Quality control and filtering

    Library sizes and gene-detection rates are plotted per sample; outliers are inspected individually rather than dropped by a blanket rule. Gene filtering keeps features expressed above a minimum count in at least as many samples as the smallest subtype group.

  3. Normalisation

    Counts are normalised for library size and variance-stabilised for anything distance-based (PCA, clustering, heatmaps). Raw counts are kept for the differential expression model, which expects them.

  4. Exploratory analysis

    PCA on the most variable genes, then hierarchical clustering with correlation distance. The clusters are compared against published PAM50 calls to check that the recovered structure matches the known one before any hypothesis is tested.

  5. Differential expression

    Subtype-versus-subtype contrasts with a negative-binomial model, Benjamini-Hochberg correction, and thresholds fixed in advance at adjusted p below 0.05 and absolute log2 fold change above 1.

  6. Pathway enrichment

    Over-representation and rank-based enrichment against Hallmark and GO gene sets, so the gene lists become biology rather than a list of symbols.

  7. Survival analysis

    Patients are split at the median expression of each candidate gene for Kaplan-Meier curves and the log-rank test, then a Cox proportional-hazards model adds stage and age so that a gene is not credited for what stage already explains. The proportional-hazards assumption is checked rather than assumed.

  8. Validation

    The strongest candidates are re-tested in METABRIC. A finding that does not replicate is reported as not replicating, not quietly dropped.

Reproducibility

Analysis code lives in a separate repository; this site holds only the exported results. Each figure reads from a single data file, so regenerating a figure means replacing one JSON object and reloading the page. 

# Reproduce the analysis
git clone https://github.com/your-handle/brca-analysis
cd brca-analysis
make data      # download and verify against the manifest
make analysis  # QC, normalisation, DE, enrichment, survival
make export    # write assets/data/results.json for the website
✎
